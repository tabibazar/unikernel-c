Ant colony optimization · dynamic problems

Most of ant colony memory isn't memory

Move the map under a running solver and its pheromone trails become lies. Keeping them still beats starting over — but a control arm shows three quarters of that advantage has nothing to do with remembering anything.

The claim being tested

Ant Colony Optimization is supposed to excel at problems that change while you're solving them. Pheromone evaporates, so the colony forgets what is no longer true and adapts instead of restarting. It's the standard reason to reach for ACO on dynamic problems.

We had a second reason to care. If evaporation reliably erases trails that point somewhere wrong, then it also erases a corrupted pheromone value — which is what made this algorithm a candidate for a platform that occasionally computes incorrectly. Stale pheromone from a changed world and corrupted pheromone are structurally the same object.

So: solve a 400-city tour for 600 iterations, then relocate a fraction of the cities. They stay in the problem and still get chosen between — but their stored trails now point at where they used to be. Run 300 more iterations. Four arms, all forked from one bit-identical starting state.

RESTART

Throw the pheromone away. The control.

RETAIN

Keep everything, lies included.

RETAIN_CLEAN

Keep it, but reset the trails that now lie.

SHUFFLE

Keep the values, destroy what they refer to. Added later — and it changed the answer.

What the first pass said

Retaining beat restarting at every change fraction, five trials each. And wiping the lying trails made things worse — a tidy confirmation that evaporation handles them better than a reset does.

The last row is impossible

At 100% relocation every city has moved. There is no old map left to remember — and memory still "won" by 1.67%.

Whatever produced that number, it cannot be memory. Which means the whole table was measuring something else, and the neat story about ghost trails needed checking rather than publishing.

The confound

A converged pheromone matrix differs from a fresh one in two ways at once. It remembers which edges turned out to be good — and it is concentrated, most of its weight on a few edges, rather than spread flat. A restart installs a uniform value everywhere.

So "retain beats restart" confounds remembered structure with low entropy. Separating them needs an arm that keeps one and destroys the other.

SHUFFLE permutes the pheromone matrix through a random relabelling of the cities. Every value survives — the concentration is untouched, bit for bit — but the correspondence between a value and the edge that earned it is gone.

Where the advantage actually comes from

The advantage retention has over restarting, split by the shuffle control. At 5% relocation remembered structure contributes a sliver. At 100% it contributes nothing at all — which is exactly what a real memory effect has to do when the world is fully replaced.

The result

Of the 2.01% advantage retention holds at 5% relocation, concentration accounts for about 1.58 points and remembered structure for about 0.43. Roughly three quarters of ACO's apparent memory advantage is not memory — it's that a low-entropy pheromone distribution exploits faster than a flat one over a short horizon.

And the control behaves correctly at the far end. At 100% relocation SHUFFLE matches RETAIN — marginally ahead, in fact — because there is nothing left to remember. Memory's contribution falls from +0.43 to zero as the world is replaced, which is the signature a genuine memory effect must show. That decay is why the split is believable rather than a story fitted to one number.

Holds up

Wrong pheromone doesn't hurt. RETAIN is never behind RETAIN_CLEAN at any change fraction, so evaporation absorbs stale trails and paying to scrub them is a net loss.

Doesn't

That ACO's edge on changing problems is mostly about remembering the old world. Mostly it's about not discarding a converged distribution — memory is the minority term.

The half that survives is the half we needed. "Evaporation is error correction" now has direct evidence, on hardware that computes correctly, with no fault injection involved. The naive retain-versus-restart comparison simply overstates the memory part by about fourfold.

Two things that nearly became findings

Final tour quality was the wrong metric. With 2-opt running on every ant, all arms converge to the same local optimum, and the first comparison reported a dead-heat tie for reasons unrelated to pheromone. The measurement is now a checkpointed recovery curve — if memory is worth anything, it's worth it early. An improvement counter prints alongside, because a run where no ant ever beats the seeded incumbent hasn't tested the pheromone at all.

Deleting cities made the key comparison meaningless. The first version removed cities rather than moving them. But a deleted city leaves the candidate lists and construction entirely, so nothing ever reads its pheromone — zeroing it cannot change a single decision. RETAIN and RETAIN_CLEAN came out bit-identical for a purely tautological reason. Relocation is the honest form of the question: the city is still there, still chosen between, and its trail is simply wrong.

400-city uniform Euclidean instances, MMAS with 2-opt, 25 ants, rho = 0.02, integer TSPLIB-rounded distances so no comparison turns on a floating-point tie. 600 iterations before the change, 300 after, 5 independent trials per point. All four arms fork from one snapshot with one RNG state, so anything that differs afterwards is the arm.

Two plumbing checks passed, and are stated because they are what separate a result from an artefact. At 100% relocation RETAIN_CLEAN resets every row, making it the same computation as RESTART — and the two came out bit-identical at every checkpoint. And RETAIN_CLEAN's cost relative to RETAIN rises monotonically with the fraction moved, as it must.
