Measured 28 August 2026

73,309 Questions

A research agent ran for 22 minutes and answered 80 questions. This is what that cost, what the same thing would cost run continuously for a fortnight, and where the projection stops being trustworthy.

What was actually run

Not a synthetic benchmark. The agent filled the two weakest columns of a survey of twenty unikernel projects — whether each supports TLS, and what network stack and libc it uses — which an earlier pass had left mostly unknown. Eighty questions, two at a time, each one a separate stateless process that searches, reads pages, and answers or admits it cannot.

Every unit recorded its own wall time, model calls, tokens in and out, and search and fetch counts. Firecrawl's credit endpoint gave measured consumption rather than an estimate, and Gemini's pricing page was read on the day.

Two things in that table are worth more than the total.

Input outweighs output 51 to 1

1.6 million tokens in, 31 thousand out. The loop re-sends the whole conversation on every step, so a six-step question transmits its own history six times. Output — the part that feels like the work — is 2% of the tokens.

That single ratio decides the economics, because input is priced at $0.30 per million and output at $2.50. Cached input is $0.03. On this workload, prompt caching is not an optimisation; it is the difference between two bills.

The model is not the expensive part

$0.56 of model against $1.82 of search and page fetching. 76% of the cost is reading the web, not thinking about it. Every conversation about agent economics I have seen focuses on the token bill; here it is the minority of spend.

The same work by hand

Each question is a targeted lookup: two to four searches, opening a repository or a documentation page, finding a licence or a last-commit date, and writing it down without getting it wrong. Call it five minutes for someone competent and careful.

Roughly three person-years of lookups for somewhere between five hundred and two thousand dollars. The ratio is the headline, and it is real. What follows is why it is also misleading.

Where the projection breaks

The queue is the constraint, not the money

Running for a fortnight requires 73,309 questions worth asking. Our entire twenty-project survey — a genuinely useful piece of work — consumed 80. That is a tenth of one percent of the fortnight. Finding four orders of magnitude more questions that anyone wants answered is a much harder problem than paying for them, and nothing in the cost model helps with it.

98.8% completion is not 98.8% correctness

One question in eighty ended without an answer. That number says nothing about whether the other 79 are right. We know they are not uniformly right: this run and the previous one disagreed about OSv — one said TLS support was available, the other that no source it read stated it. Same agent, same question, different day.

Two runs disagreeing is the cheapest possible reminder that a single run is evidence, not truth. Verification costs roughly what generation costs, which halves the effective rate and is not in the table above.

Nobody reads 73,309 answers

The output would be about 70 MB of prose. Turning that into something usable needs an extraction pass — we ran one, and it needed its own model calls — and then human curation, which is exactly the cost the agent was supposed to remove. The bottleneck moves from producing answers to deciding which ones matter.

Unattended for a fortnight is a fiction

In 22 minutes of running, three failure modes appeared that needed a person: concurrency tripping the search API's rate limiter, a tool schema the model kept malforming, and a question so large it exhausted the step budget before the agent would commit. Each needed a code change. A fourteen-day run assumes none of that happens for two weeks, which is not what any two-week period looks like.

This is the honest argument for a supervising agent rather than a bigger prompt: something has to notice at 3am that the queue has stopped moving, work out why, and either fix it or say clearly that it cannot.

And the rate limits bite before the budget does

456,349 model calls in a fortnight is 22.6 a minute, sustained, day and night. That is comfortably past free-tier limits. The $509 figure is not a way to get the work for free; it is what the work costs once you are paying properly for it.

What the 22 minutes actually produced

The run was not a demo. The survey's most important column — can this project do TLS, the line between a research toy and something that can face the internet — went from 3 of 20 established to 8, with the library named in each case: ocaml-tls for MirageOS, BearSSL for HermitOS, OpenSSL and others ported for Unikraft, a tls klib for Nanos, RA-TLS for Gramine. Solo5 was established as not providing TLS itself, which is equally useful to know.

That is thirty cents of API time against several hours of a person's afternoon, and it is the honest scale at which this technology is currently worth deploying: not seventy thousand questions, but the eighty you actually needed and were not going to do by hand.
